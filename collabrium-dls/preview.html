The operating system for Astro's digital growth engine — connecting Sales, Media, Influence, Content, and Studio into one system of record.

Collabrium — Astro Digital Growth [OS]. From Collaboration + Equilibrium. It's the shared home for Astro's digital teams: where six functions (Content, Product, Marketing, Sales, Commercial, Editorial) stop working around each other and start working together, without losing what makes each one good at its job. Unlike siloed tools bolted on team by team, Collabrium starts from the infrastructure up.

"Collabrium is where Astro's Sales, Media, Influence, Content, and Studio teams stop working in parallel and start working together — so no rep, no editor, no strategist is ever the last to know. Built from the ground up to bring people together, not just tools." — Positioning statement

The name isn't decorative — it states the argument. Collaboration is one shared system: Content, Product, Marketing, Sales, Commercial, and Editorial working as one, not six. Equilibrium is balance restored across execution, measurement, and allocation — not just speed for its own sake.

Voice: write like you're talking to a teammate, not briefing a system. Favor warm, human verbs (see, share, meet in the middle) over mechanical ones (sync, deploy, restore). Keep it short and plain — confidence doesn't need extra words.

05 · Foundations

Spacing & Shape

4pt base grid. Collabrium is a product surface, not a marketing page — most layouts run full-bleed within the app shell rather than centering. Radius is per-surface, not one flat scale. Values sourced from a teammate's fuller extraction of the same source deck — see DESIGN.md Changelog.

Elevation

A real shadow ladder — not "flat by default." Every shadow is built on Neutral-4 (soft grey), never black. Cards and dialogs use these regularly.

Motion

"Movement settles; it never bounces." One easing curve per element, used when motion is thematically tied to that element; --ease-standard is the default for everything else.

06 · Reference

Guidelines

The condensed, skimmable version of every rule in this system. Full detail and rationale in the DESIGN.md tab.

Do

  • Use Obsidian as the only primary-action fill — one Primary button per screen.
  • Use the warm canvas (#FCFAF5) as the page background for every screen — product/dashboard and brand/editorial alike. Component fills (cards, inputs, etc.) keep their own values, mostly Neutral-1 white.
  • Use Mulish for 100% of UI text and every heading — headings at weight 800, letter-spacing 0.
  • Reserve Source Serif 4 for genuine brand-statement moments only (deck ledes, pull quotes, hero numerals), never as a heading-token swap, never below ~18–20px.
  • Use the tinted-fill + bordered pattern for every Badge, and darken Success/Warning text (#00854c, #9a5c00) so it clears AA.
  • Map department/element colors 1:1 from the Color Palette table — don't invent one.
  • Tint a surface only with the element that already owns its content, and only at the -bg (8%) or -bg-strong (16%) step.
  • Use Regular weight for functional/control icons (Tier 1) and Fill for expressive/status icons (Tier 2) — the weight is decided by what the icon does, not by taste.
  • Pull every spacing, radius, and color value from a token — no arbitrary values.
  • Let cards carry shadow-1 at rest, and build every shadow on Neutral-4 (soft grey), never black.
  • Keep radius soft: 20px cards, 16px buttons, 12px inputs. Never below 12px on an interactive surface.
  • Give every interactive component its full state set: hover, active, focus, disabled, error.
  • Right-align numeric table columns with tabular figures.

Don't

  • Never use a brand/element color as a primary button fill — those colors classify, they don't mean "click me."
  • Never use Source Serif 4 in body copy, buttons, inputs, table data, or dense numeric columns.
  • Never mix two fonts inside a single sentence or heading — emphasis is a weight change, not a font swap.
  • Never apply negative letter-spacing to headings — Collabrium headings are weight 800 at tracking 0.
  • Never assign icon weight by taste — Regular for Tier 1 (functional/control), Fill for Tier 2 (expressive/status) — and never mix Phosphor with Remix within the same component instance.
  • Never build a shadow on black — every shadow in this system is Neutral-4 based.
  • Never fill a small badge solid with a brand color and put white text on it — several accents fail contrast that way.
  • Never use a radius outside the token set (radius-sm/md/lg/pill/link).
  • Never tint a surface with an element that doesn't own its content, and never at full or mid strength.
  • Never add bounce or overshoot easing — movement settles.
  • Never use placeholder text as a substitute for a real label.
  • Never use a modal for a multi-step flow.
  • Never let a table exceed ~8–10 visible columns without a collapse pattern.
  • Never treat a ⚠️ value in DESIGN.md as final — it's a draft until the brand team signs off.
